Нилов Дмитрий Александрович, ИДБ-23-02. Вариант 15.

Оконное приложение на Go и Fyne: вход, установка и смена пароля, управление пользователями, блокировка, индивидуальные ограничения и файловое хранение.

## Запуск

Из каталога `Лаба 1`:

```sh
go run ./src
```

Готовый Linux-бинарник после сборки:

```sh
make build
./bin/lab1
```

Первый вход: имя `ADMIN`, пароль оставьте пустым. Затем дважды введите новый пароль, например учебный `aя+`. До установки пароля административные команды недоступны.

Файл `data/users.json` создаётся автоматически только с ADMIN. Все изменения сохраняются сразу. При повторном запуске используйте установленный пароль. Старый экспериментальный `users.json` в корне не используется и не изменяется.

Для отдельной демонстрации можно выбрать другой файл:

```sh
./bin/lab1 -data /tmp/lab1-demo/users.json
```

Один файл может использовать только один экземпляр приложения. Ошибка открытия или повреждение файла выводятся в терминал, файл не пересоздаётся.

Для сборки нужны Go 1.27, C-компилятор и библиотеки OpenGL/X11. Требования Fyne: https://docs.fyne.io/started/quick/. На Arch Linux обычно достаточно установленных `go`, `gcc`, `pkgconf`, `libglvnd`, `libx11`, `libxcursor`, `libxrandr`, `libxinerama`, `libxi`, `libxxf86vm`; на Debian/Ubuntu — `golang`, `gcc`, `pkg-config`, `libgl1-mesa-dev`, `xorg-dev`. Программа проверена на Linux; Windows/macOS не входят в проверенную сборку, файловая блокировка использует Linux/Unix.

## Работа с программой

ADMIN через меню «Администрирование» или кнопки открывает весь список пользователей, добавляет уникальное имя и меняет параметры выбранной записи. Новый пользователь получает пустой пароль, включённое ограничение и выключенную блокировку. ADMIN не задаёт чужой пароль. Блокировка самого ADMIN запрещена, чтобы сохранить административный доступ.

Пользователь при первом входе устанавливает пароль, после чего может менять его с проверкой старого. Для смены и первой установки нужны совпадающие пароль и подтверждение. Новый пустой пароль запрещён независимо от флага ограничения.

Меню «Учётная запись» позволяет сменить пароль, выйти из аккаунта или завершить программу. «Справка → О программе» содержит автора, группу и индивидуальное задание. При выходе из аккаунта программа продолжает работать; при завершении закрывается весь процесс.

Во всех полях пароль отображается звёздочками без раскрытия. Поддерживаются ввод, стрелки, Home/End, Backspace/Delete и вставка из буфера. Копирование, вырезание, выделение и отмена в полях пароля отключены.

Третий неверный пароль при входе прекращает доступ; кнопка в финальном сообщении закрывает программу. Счётчик общий для запуска, не сбрасывается успешным входом или выходом из аккаунта. Неизвестное имя, блокировка, ошибки нового пароля и старого пароля при смене не увеличивают счётчик. Новый запуск начинает счётчик с нуля и не снимает административные блокировки.

## Вариант 15

«Наличие латинских букв, символов кириллицы и знаков арифметических операций».

При включённом флаге нужны латинская буква, кириллическая буква и хотя бы один знак `+ - * / %`. Цифры, разные регистры и минимальная длина дополнительно не требуются. Unicode-профиль учитывает буквы Latin и Cyrillic, включая Ё/ё, Ї и é. Пароли сравниваются точно, без удаления пробелов и нормализации.

| Пароль | Результат при включённом ограничении |
|---|---|
| `aя+`, `AЯ-`, `qЖ*`, `bю/`, `mф%` | Принимается |
| `abcЯ!`, `AaАа1!` | Нет арифметического знака |
| `Aa+` | Нет кириллицы |
| `Аа+` | Нет латиницы |
| `abcЯ=` | `=` не входит в заданный набор |

Выключенный флаг снимает проверку состава, поэтому непустой `123` можно выбрать. Если затем включить флаг, вход с сохранённым `123` останется возможен; при следующей смене новый пароль уже обязан пройти вариант 15.

## Проверка и демонстрация

```sh
make test
make race
make vet
make build
```

Тесты используют временные каталоги и Fyne test app, рабочие учётные записи не меняют. Для экспорта изображений форм:

```sh
LAB1_SCREENSHOTS=/tmp/lab1-screens go test ./src -run TestUIScreenshots -count=1
```

1. Запустите на отдельном файле. Войдите ADMIN с пустым паролем.
2. Попробуйте `abcЯ!`, получите отказ, затем установите `aя+` с подтверждением.
3. Создайте `student`. Выйдите из аккаунта, войдите student с пустым паролем, установите `mф%`.
4. Убедитесь, что у student отключены административные пункты меню.
5. Войдите ADMIN и выключите проверку варианта 15 у student.
6. student меняет пароль с `mф%` на `123`, указывая правильный старый пароль.
7. ADMIN включает проверку. student входит по `123`; смена на `456` отклоняется, на `qЖ*` проходит.
8. Перезапустите программу, проверьте сохранённые записи и параметры.
9. ADMIN блокирует student; попытка его входа отклоняется. Затем можно снять блокировку.
10. Откройте справку. На отдельном запуске трижды ошибитесь паролем и закройте финальное сообщение.

Примеры паролей предназначены только для демонстрации.

## Файлы

`src/service.go` содержит правила и права, `policy.go` — вариант 15, `password.go` — Argon2id со случайной солью, `store.go` — JSON и атомарную запись, `lock.go` — блокировку экземпляра. `ui.go` содержит формы Fyne, `password_entry.go` — звёздочки вместо текста пароля. В JSON сохраняются хеши, не исходные пароли; хеширование является способом хранения для первой лабы. Шифрование файла и парольная фраза из лабораторной 3 не реализуются.

Проверенные ТЗ и план находятся в `docs`. Отчёт описывает реализацию и результаты проверки. Исходные PDF и DOC сохранены без изменений.
