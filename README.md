# Защита информации - лабораторная работа №1 Вариант 15.

## Задание

Сделать программу с входом по имени и паролю и разделением прав администратора и обычного пользователя. Администратор должен управлять учётными записями, а пользователи - устанавливать и менять свои пароли. Данные должны сохраняться в файле между запусками.

По варианту пароль должен содержать латинскую букву, букву кириллицы и знак арифметической операции: `+`, `-`, `*`, `/` или `%`.

## Что сделано

Приложение написано на Go с графическим интерфейсом Fyne.

- Вход, первая установка пароля и смена с проверкой старого пароля.
- Для ADMIN: список пользователей, добавление учётных записей, блокировка и включение ограничений пароля.
- Проверка пароля и его подтверждения. При вводе отображаются звёздочки.
- Завершение программы после трёх ошибок пароля за один запуск.
- Сохранение пользователей и настроек в JSON. Вместо паролей хранятся хеши Argon2id.
- Меню «О программе» с данными автора и заданием.

## Запуск

Сборка рассчитана на Linux. Нужны Go 1.27, C-компилятор и библиотеки OpenGL/X11.

Из папки проекта:

```sh
make run
```

Или собрать исполняемый файл:

```sh
make build
./bin/lab1
```

## Как пользоваться

1. При первом запуске войдите под именем `ADMIN`, оставив пароль пустым.
2. Установите пароль и повторите его в поле подтверждения. Например, `aя+` подходит под ограничения.
3. Через меню «Администрирование» добавьте пользователя. Там же можно заблокировать его или включить и выключить ограничения пароля.
4. Выйдите из аккаунта и войдите под именем нового пользователя с пустым паролем. Он также должен установить свой пароль.
5. Для смены пароля откройте соответствующий пункт меню «Учётная запись» и введите старый пароль, новый и подтверждение.

Обычному пользователю административные действия недоступны. ADMIN не может заблокировать себя или назначить пароль другому пользователю.

Если ограничения выключены, можно установить любой непустой пароль. Включение ограничений не меняет уже сохранённый пароль: проверка применяется при следующей смене.

Данные сохраняются автоматически в `data/users.json`. При следующем запуске используйте установленный пароль. Для работы с отдельным файлом:

```sh
./bin/lab1 -data data/demo.json
```

## Проверки

```sh
make test
make lint
```

Для `make lint` нужен установленный `golangci-lint`. Тесты работают с временными файлами и не меняют рабочие учётные записи.

Исходники находятся в `src`, задание и отчёт - в `docs`.
