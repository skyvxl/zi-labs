## Задание

Добавить к первой лабораторной шифрование файла пользователей. При запуске запрашивать парольную фразу, расшифровывать записи и проверять наличие ADMIN. При неправильной фразе или отмене завершать программу. После работы сохранять файл зашифрованным и удалять временные открытые данные.

По варианту нужны блочный шифр, режим CFB, случайное значение для ключа и MD5.

## Что сделано

Приложение на Go и Fyne для Linux. Вместо Windows CryptoAPI используются криптографические пакеты Go — это отступление от исходного задания по выбранному способу реализации.

- AES-128 в режиме CFB. Ключ получается из MD5 случайной соли и парольной фразы.
- Соль создаётся при создании файла, новый IV — при каждом сохранении. Соль и IV хранятся рядом с шифротекстом.
- HMAC-SHA256 проверяет целостность файла перед расшифровкой. Наличие корректной записи ADMIN проверяется после неё.
- Открытые записи хранятся только в памяти. Временный файл при сохранении тоже зашифрован.
- Изменения сохраняются сразу. При закрытии файл шифруется снова; если запись не удалась, программа показывает ошибку и позволяет повторить сохранение.
- Сохранены вход, смена пароля, управление пользователями и ограничения из первой работы.

MD5 используется по условию лабораторной для ключа файла. Пароли учётных записей по-прежнему хранятся как хеши Argon2id.

## Запуск

Нужны Go 1.27, C-компилятор и библиотеки OpenGL/X11 для Fyne.

Из папки проекта:

```sh
make run
```

Или собрать программу:

```sh
make build
./bin/lab3
```

## Как пользоваться

1. При первом запуске задайте парольную фразу файла и повторите её. Она открывает весь файл пользователей.
2. Войдите под именем `ADMIN` с пустым паролем и установите пароль аккаунта. Например, `aя+` подходит под ограничения. После установки введите имя и новый пароль на экране входа.
3. Дальше работайте как в первой лабораторной: добавляйте пользователей, меняйте параметры и пароли.
4. Завершите работу через меню или закрытие окна.
5. При следующем запуске сначала введите парольную фразу файла, затем имя и пароль своего аккаунта.

После любой смены пароля нужно заново ввести имя и пароль. Если администратор включил ограничения, а текущий пароль им не соответствует, при следующем входе потребуется его сменить. До этого действия в аккаунте недоступны.

Неверная парольная фраза выводит сообщение с кнопкой завершения. Повторного ввода в этом запуске нет. Отмена также показывает сообщение о завершении.

Файл сохраняется в `data/users.enc`. Для отдельной базы:

```sh
./bin/lab3 -data data/demo.enc
```

Первая лабораторная и её учётные записи остаются в своей папке. Эта версия начинает с новой базы; открытый JSON первой работы автоматически не импортируется.

## Проверки

```sh
make test
make lint
make race
```

Для lint нужен `golangci-lint`. Тесты работают с временными файлами. Они проверяют шифрование, повреждение файла, неверную фразу, ADMIN, сохранение и действия в интерфейсе.

Исходники — в `src`, исходное задание и описание реализации — в `docs`.

## Проверка повреждения файла

Закройте программу и сделайте копию `users.enc`. В hex-редакторе измените один байт, запомнив его позицию и исходное значение. Сохраните файл и запустите программу: при открытии базы появится ошибка. Завершите программу через это сообщение, верните исходный байт, сохраните файл и запустите снова — база должна открыться.

При каждом успешном сохранении и закрытии программа создаёт новый IV и шифрует файл заново, поэтому его байты меняются даже без изменения учётных записей. Ошибка открытия повреждённой базы файл не перезаписывает. Если править файл при работающей программе, последующее сохранение заменит его данными из памяти.

Для такого опыта удобнее hex-редактор: обычный текстовый редактор может изменить кодировку или сразу несколько байтов двоичного файла. Копия позволяет восстановить весь файл, если точную правку отменить не удалось.
